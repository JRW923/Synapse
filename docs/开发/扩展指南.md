# Synapse 扩展指南：新增 Provider / Tool / Planner

本指南回答一个问题：**扩展 Synapse 为什么不需要改 Agent 主循环**。答案分三层——协议（要实现什么）、容器（在哪注册）、边界（谁来保证你不越界）。`examples/extensions/` 下有两个可直接运行的最小示例。

## 三层结构

| 层 | 位置 | 职责 |
|---|---|---|
| 协议 | `synapse/protocols/` | 定义 `LLMProvider`、`Tool`、`Planner`、`Memory` 等接口，纯数据结构 + 方法签名 |
| 容器 | `synapse/core/`（IoC Container） | 组装与解析：实现类在这里注册，运行时在这里被替换 |
| 边界 | `tools/check_boundaries.py` + `tests/test_architecture_boundaries.py` | AST 检查包依赖方向，保证扩展点不被绕开 |

`modules/` 只能依赖 `core/modules/protocols`，不得 import `adapters`；`protocols` 不依赖任何层。新增组件落在 `modules/`（或独立文件），主循环（`core/agent.py`、`modules/planning/react.py`）只面向协议方法调用，对你的实现一无所知。

## 示例 1：自定义 Provider（约 40 行）

见 `examples/extensions/echo_provider.py`。最小实现只需 `model_id` 属性与 `chat()`（`stream()` 可选——没有它时主循环自动回退到 `chat`）。

注册方式：

```python
from synapse.adapters.library import Synapse
from synapse.core.container import Container  # 按你的组装路径
from synapse.protocols.llm import LLMProvider
from examples.extensions.echo_provider import EchoProvider

synapse = Synapse(provider="openai", model="gpt-5.4")   # 先用任一已注册 provider 启动
synapse._container.register(LLMProvider, EchoProvider())  # 替换模型层
result = await synapse.run("any task")
```

此后 ReAct/PlanExecute/Swarm 全部走你的实现；上下文治理、授权、审计、评测不打折。

## 示例 2：自定义 Tool（约 35 行）

见 `examples/extensions/timestamp_tool.py`。需要 5 个类属性（`name/description/parameters/requires_sandbox/risk_level/category`）加一个 `async execute(params, sandbox) -> ToolResult`。

注册方式：

```python
from synapse.modules.tools.registry import DefaultToolRegistry
from examples.extensions.timestamp_tool import TimestampTool

synapse._container.resolve(DefaultToolRegistry).register(TimestampTool())
```

工具即刻对模型可见（schema 自动进入提示）。**注意安全边界**：`risk_level` 决定它在 action-time 授权中走哪条路径——`READ_ONLY` 免确认、`WRITE_LOCAL` 受工作区/文件域约束、`EXECUTE` 走命令链解析、`EXTERNAL` 需显式开启。标低风险不会绕开注入扫描（外部来源输出仍会被 InjectionGuard 包装）。

## 新增 Planner

实现 `protocols/planner.py` 的 `Planner` 接口（`execute(task, context, tools, llm, sandbox, session, event_bus) -> AgentResult`），在 `adapters/library.py` 的 `_build_planner` 模式映射中加一行。Swarm/PlanExecute 都是这个模式的现存范例。

## 怎么证明"零主循环改动"

1. `pytest tests/test_architecture_boundaries.py` —— 包依赖方向的 AST 回归。
2. `pytest tests/test_extension_examples.py` —— 加载 `examples/` 的两个扩展并实际执行。
3. 新增一个 Provider 的 diff 就是 `echo_provider.py` 一个文件 + 一行注册；新增一个 Tool 同理。对比主循环文件（`react.py`）的 diff 为零。

## 已知边界

- Plugin 系统当前是 manifest 门控（发现 + 版本校验），不 import 第三方代码；动态加载属于刻意未做的供应链安全取舍（见 README「工程边界」）。
- 自定义 Provider 的 usage 统计质量取决于你在响应里返回的 `usage` 字典；不返回则 Token/成本报告按缺失处理。
