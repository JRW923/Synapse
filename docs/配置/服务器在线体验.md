# 服务器在线体验

> ⚠️ 普通用户请用 [本地网页体验](本地网页体验.md)（在自己机器上跑、用自己的 Key）。
> 本文仅适用于**受信任团队内网共享**的服务器托管场景，且需服务器能出网到 LLM、并自行解决多用户隔离与沙箱。

Synapse 的 Web UI 能读写工作区并执行经确认的命令，不能作为匿名公共服务部署。本环境用 Cloudflare Access 限制为受信任账号访问，服务本身以非 root 用户运行，只能写入独立 Docker 卷中的 `/workspace`。

## 前置条件

- `/root/.synapse/models.json` 已配置可用的 OpenAI-compatible 模型。该文件包含密钥，只读挂载到容器，禁止提交到 Git。
- Cloudflare Zero Trust 中创建 `synapse.jrwdev.site` 的 Public Hostname，目标选择现有 Tunnel。
- 为该域名创建 Cloudflare Access Application，仅允许自己的邮箱或受信任组织登录。不要创建 `Everyone` 策略。

## 发布与验证

在 `/opt/EventGuard` 执行：

```bash
docker compose config
docker compose up -d --build synapse cloudflared
docker compose ps synapse
docker compose logs --tail=100 synapse
docker compose exec synapse python -c "import urllib.request; print(urllib.request.urlopen('http://127.0.0.1:8000/health').read().decode())"
```

健康检查返回 `{"status":"ok"}` 后，访问 `https://synapse.jrwdev.site/`。个人主页的“在线体验”按钮也指向这个地址。

## 边界

- Web UI 保留逐次操作确认，不允许自动批准。
- 工作区、会话与本地记忆保存于 Docker 命名卷；它们属于这一个受保护的在线实例，不是多用户隔离实现。
- 如需面向匿名访客开放，必须先增加身份体系、用量限制、独立工作区和更强的每任务沙箱，不能移除 Access 后直接公开。
