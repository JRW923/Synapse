# Synapse 模型配置方案

## 目标

将模型注册、默认选择和凭据与项目级工具、规划和安全配置分离，让用户首次配置后可零参数启动，并能在交互会话中安全切换模型。

## 配置职责

| 文件或来源 | 职责 |
|---|---|
| `~/.synapse/models.json` | Provider、模型列表、默认模型和凭据。 |
| `synapse.yaml` | 可选的项目级工具、规划、安全、hooks、插件覆盖；不保存模型密钥。 |
| 环境变量 | 临时覆盖 API key 或默认模型，优先级最高。 |
| CLI 参数 | 仅对当前命令生效的显式覆盖。 |

## 行为约定

- 首次启动缺少模型配置时进入向导，API key 不回显。
- `/model` 切换会持久化默认选择；`/model add` 可新增兼容 Provider 配置。
- Library API 只有传入 `provider` 或 `model` 时才覆盖已加载配置。
- 配置文件损坏、默认模型不存在或模型列表重复时快速失败并指出修复位置。
- 当前仓库不提供 `synapse.yaml`；只有确有项目级覆盖需求时才创建该文件。

## 已知范围

当前不支持热重载、OAuth、shell command 凭据解析或复杂模型能力元数据；这些需求尚无足够使用场景，不应为此增加配置复杂度。
