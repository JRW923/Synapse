# Synapse 系统设计说明

## 项目定位

Synapse 是面向代码仓库任务的本地 Code Agent Harness。它把模型调用、规划、工具执行、状态管理、安全控制和评测收敛为可替换的运行时边界，解决长任务中上下文失控、状态中断、工具副作用不可控和结果难以验证的问题。

## 设计原则

- 协议优先：`protocols/` 定义稳定契约，`modules/` 提供可替换实现。
- 运行时治理：每次工具调用在执行时重新鉴权，而非只依赖工具注册时的静态标签。
- 证据优先：任务是否完成由外部 grader、测试和运行事实确认，不接受模型自述。
- 最小持久化：会话、项目与用户信息按生命周期拆分，敏感内容不进入评测报告。

## 架构边界

| 层级 | 职责 | 主要位置 |
|---|---|---|
| 协议层 | Provider、Tool、Planner、Memory、Sandbox、MCP 等接口与数据模型 | `synapse/protocols/` |
| 核心层 | 生命周期、会话、事件总线、依赖装配与异常模型 | `synapse/core/` |
| 模块层 | 规划、记忆、上下文、安全、工具、Provider、MCP 与评测实现 | `synapse/modules/`、`synapse/eval/` |
| 适配层 | CLI、HTTP、Library API 和配置加载 | `synapse/adapters/`、`synapse/config/` |

`EventBus` 是横切通道：安全、过程质量、效率和审计模块订阅运行事件，不侵入 Agent 主循环。

## 任务执行

1. Adapter 加载配置，创建 `Synapse` 与独立 Session。
2. Planner 结合任务、检索结果和记忆生成模型请求及工具调用。
3. 工具调用依次经过授权、沙箱和工作区边界校验。
4. EventBus 记录模型、工具、授权和文件写入事实，评测模块汇总为 `RunScore`。
5. Completion Gate 检查变更与验证证据；需要功能结论时由外部 grader 再次验证。

## 上下文与记忆

- 上下文：Git-aware 检索、符号提取、分区预算和摘要压缩控制 prompt 规模；检索或压缩异常时降级，不中断任务。
- 记忆：Session、Project、User、Semantic 四层存储分别承担本轮状态、仓库事实、偏好规则和检索增强；恢复前校验 workspace 漂移，避免将旧状态带入新仓库。
- 已知边界：检索主要依赖关键词与轻量规则，不等同于完整 AST 或语义检索系统。

## 工具与安全

- 风险分级覆盖只读、工作区写入、进程执行、外部访问和元操作。
- `ActionAuthorizer` 在 action-time 检查命令链、重定向、敏感路径与工作区范围；高风险操作拒绝或要求确认。
- `ProcessSandbox` 负责超时和进程树回收；默认不是文件系统级隔离，强隔离依赖受控容器环境。
- 外部来源内容带有 trust annotation，并以 `<external-content>` 标注进入模型上下文。

## 扩展机制

- Provider：通过兼容协议接入多家模型服务；配置与密钥管理见[模型配置方案](../配置/模型配置方案.md)。
- Planner：支持 ReAct、Plan-Execute、Hierarchical 与 Swarm；规划策略可替换，不改变工具和安全边界。
- MCP：以 Client、Manager、Tool Wrapper 分层接入 stdio 与 HTTP transport，远程工具默认视为外部风险。
- Skills 与插件：在明确授权下加载，运行时能力摘要会写入评测证据。

## 验证与限制

评测架构、指标与证据边界见[评测体系方案](../评测/评测体系方案.md)。当前已验证官方 SWE-bench 单题环境与真实模型单题链路；尚未完成多任务、重复的跨 Harness 统计实验，因此不对 Harness 优劣或能力提升作百分比结论。
