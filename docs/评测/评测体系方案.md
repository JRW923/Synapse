# Synapse 评测体系方案

## 目标与边界

评测需要同时回答四件事：补丁是否正确、运行是否稳定、资源消耗是否可接受、工具调用是否符合安全和过程约束。单题、单次、无外部 grader 的结果不能回答 Harness 是否更优。

## 指标体系

| 层级 | 主指标 | 用途 |
|---|---|---|
| 功能正确性 | 外部 grader 的 task success、grader score | 唯一可用于功能结论的指标。 |
| 稳定性 | Pass@k、Pass^k、Wilson 95% CI、失败率 | 区分任务数与重复 attempt。 |
| 效率 | 输入/输出 Token、成本、耗时、工具成功率 | 只在 usage 完整时报告精确值。 |
| 过程与安全 | 检索、根因、测试留存、授权拦截、越界与注入信号 | 用于诊断和 guardrail，不替代功能分。 |
| Grader 质量 | false accept、false reject、grader error | 防止错误评分器制造伪结论。 |

## 可比性协议

- 同一任务、基线、模型标识、权限与预算下比较 Harness。
- 每个 attempt 使用隔离 workspace；只有显式 sequence 才允许复用状态。
- A/B 按共享 seed 配对，记录执行顺序、模型实际 ID、配置指纹和外部 grader 事实。
- 数据、grader、镜像或代码版本变化时新建 series，不跨 series 比较。

## 数据与证据治理

- Dataset manifest 冻结版本、来源、许可证、任务 hash、split、tombstone、grader 与镜像信息。
- 实验预注册固定主指标、MDE、alpha、样本量、重复次数、guardrail 和停止规则。
- Golden cases 覆盖近似正确、删除测试、硬编码、空实现与越界修改；结果用于校准 grader。
- 失败产物可进入内容寻址 artifact store，公开报告仅保留 URI、SHA-256、字节数与类型。
- append-only run registry 保存 report、代码、数据、grader、镜像和配置指纹，趋势分析按同一 series 运行。

## 统计规则

- 任务相关时使用 repository-cluster bootstrap，而不是把同仓库题目当独立样本。
- 配对二值结果使用 McNemar；连续指标使用配对随机化检验；主指标与 guardrail 同时进入多重比较控制。
- 单题、单个配对或不完整配对统一标记为 `inconclusive`，不产生 winner。

## 当前限制

- 尚未运行冻结多任务、重复的 Synapse/Aider 成对实验，不能发布 Harness 或模型能力排名。
- Flash/Pro 为同一模型家族，不能满足“两个独立模型族”的严格实验要求。
- 默认进程树沙箱不等同于容器级文件系统隔离；跨 Harness 权限等价性仍需正式环境取证。
- 定时 CI 只跑离线 fixture；收费模型只允许受保护环境中显式触发。

## 验收要求

正式结论至少需要：冻结数据和可信外部 grader、稳定的 golden-case 审计、预注册的样本量与停止规则、完整的 Token/cost 覆盖、最小任务切片样本量，以及可回查的不可变报告记录。
