# Synapse 评测基线与外部接入

## 结论

Synapse 的本地评测层用于验证运行时、grader 和报告契约；它不替代官方 benchmark runner。对外结论必须区分工程回归、单题 smoke 与冻结多任务实验。

## 已建立能力

| 层级 | 作用 | 证据边界 |
|---|---|---|
| Benchmark Runner | 调度任务、重复运行、汇总统计与报告 | 无外部 grader 时只记录 Agent 状态。 |
| `repo_pytest` | 临时 Git 仓库加 pytest grader 的离线功能基准 | 用于确定性回归和真实模型接线。 |
| Process Quality | 根据 EventBus 事实诊断检索、根因、测试留存和过程质量 | 是诊断指标，不是通用能力分。 |
| SWE-bench 适配 | 隔离 checkout、补丁提取与私有测试执行 | 本地适配结果不能冒充官方榜单。 |
| Terminal-Bench 适配 | 导入任务、基线 preflight 与外部 grader | 需要可信任务数据和运行环境。 |
| 外部 Harness | JSON v1 命令协议与实际模型/权限/预算核验 | 子进程声明不满足核验条件时不计入可比结论。 |

## 外部框架选择

- SWE-bench Verified：代码修复任务的功能正确性验证，官方 runner 作为可信执行环境。
- Terminal-Bench：终端操作任务与环境交互评测。
- 自建过程质量与红队：补足公共 benchmark 不覆盖的安全、证据和长任务治理问题。

未接入的 GAIA、ToolBench、τ-bench 等框架不是缺失功能，而是尚未证明与代码仓库任务的收益足以抵消运行和维护成本。

## 冻结 20 题多任务正式 run（2026-08-16）

从 500 条冻结 split 按 seed 分层选出 20 题（django 4.2–5.0 ×9、sympy 1.7–1.12 ×10、sphinx 5.0 ×1），全部通过 **gold patch 入库验证**（官方解在本环境实测通过 FAIL_TO_PASS 后才入库），per-repo grader 命令（django 官方 `runtests.py` 标签级、其余 pytest 节点级）。冻结集 SHA-256 `55f4be7b66110e32fc4abfbedeccead281108da542d41ceaf1f7db0ba2d78be2`。

同一 Harness（commit `5684c8c`）、同一冻结集、同一 grader，经第三方 OpenAI 兼容网关的三档模型各 20 题 × 3 runs：

| 模型（网关定价 $/1M in/out） | task success@3 | attempt 通过率 [95% CI] | 成功误报率 | Token / 成本 | 解题时长（成功中位） |
|---|---|---|---|---|---|
| gpt-5.4-mini（0.75/4.5） | 8/20 = 40%* | 12/49 有效 = 24.5% | 72.2% | 7.7M / $24.3 | 117s |
| gpt-5.4（2.5/15） | 11/20 = 55.0% [34.2, 74.2] | 17/60 = 28.3% [18.5, 40.8] | 76.9% | 11.9M / $37.6 | 128s |
| gpt-5.5（5/30） | 8/20 = 40.0% [21.9, 61.3] | 13/60 = 21.7% [13.1, 33.6] | 58.3% | 12.0M / $38.0 | 126s |

\* mini 轮 11 个 attempt 因网关 503 中断（渠道后下架），16 题有效口径为 50%；该轮教训促成了 LLM 失败分类改造（网关 5xx 计入 `infrastructure_failure_attempts`）。

**口径限定（必须随数字一起出现）**：

- 经由第三方网关，模型真实性不可验证；gpt-5.5 与 gpt-5.4 的差异在 20 题样本下不具统计显著性（CI 大量重叠），不能作为模型能力结论。
- 本地 Windows 单 venv 环境（Python 3.14 + 版本对齐依赖），非官方 runner 口径；gold-verified 入库与外部 grader 保证"数字可信"，不冒充官方榜单成绩。
- 时间分解（迭代数 9.6→10.6→11.8 单调上升、解题时长 117→128→126s 微增后持平）显示：时长主要受迭代数 × 渠道速度驱动，更强模型以更多自我验证步骤抵消了试错减少的收益；渠道间单次调用速度差可达 28 倍（smoke 实测），是效率对比的最大混淆项——per-call 延迟记账（commit `f72a31f`）为下一轮提供干净分离。
- 成功误报率 58–77%（模型自报成功被外部 grader 否定的比例）是本轮最有说服力的发现：外部 grader 不可或缺，且模型越强自报越自信。

三 run 已登记入 `eval-results/registry/registry.json`（series `swebench-frozen20-202608`，verify 通过、comparable）。

## 报告解释

- `verified`：可信 grader 已执行并给出结果。
- `agent_status_only`：只有 Agent 状态，不可作为功能成功。
- `not_graded`：未执行或不具备 grader 条件，不进入能力统计。
- `grader_error`：grader 或基础设施失败，必须与模型失败分开统计。
- `failure_kind=provider_unavailable`（2026-08 起）：LLM 网关 5xx/超时/连接中断，计入 `infrastructure_failure_attempts`，不作为模型失败。

报告会生成 JSON、HTML 与 CSV；Token、成本和工具成功率只在 Provider 返回完整 usage 时计算。Aider 未提供完整 Token/cost 时，其结果不能进入效率对比。

## Grader 环境的教训（2026-08 修正）

- 旧环境存在"verified 有水分"问题：grader 的 pytest 因缺依赖 collection error 也返回非零，与真实测试失败无法区分（gold patch 在旧环境同样跑不过）。修正：**gold patch 入库验证**成为任务集准入门槛——官方解在当前环境实测通过后才入库，此后 `tests_passed=false` 才能解释为模型修复不完整。
- Windows 单 venv（Python 3.14）的版本边界：缺 `distutils`（setuptools shim 修复）、缺 `pkg_resources`（setuptools<81 修复）、django<4.1 依赖已被移除的 `cgi` 模块（解释器级不可修，任务集按版本过滤）。官方 SWE-bench 使用 per-task Docker 正是为此；本地适配层的这一天花板已显式记录。
