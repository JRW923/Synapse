# Synapse 架构审查与改造记录

## 审查结论

Synapse 的核心价值在于将 Agent Loop、工具授权、上下文、记忆和评测置于明确的协议边界内，而不是简单封装模型 API。当前架构适合继续以 Python 演进，不需要为了语言统一进行全量 TypeScript 重写。

## 已验证优势

- Protocol、IoC 和 EventBus 分离了生命周期、实现策略与横切观测。
- Action-time 授权、工作区边界、进程树回收和审计覆盖了工具调用的关键风险点。
- 分层记忆、上下文预算和恢复校验面向仓库级长任务，而非单轮问答。
- Completion Gate、外部 grader、冻结 manifest 和配对实验将“完成”转为可审计事实。

## 主要边界

| 领域 | 当前边界 | 后续方向 |
|---|---|---|
| 沙箱 | 默认是进程树治理，不是完整文件系统隔离 | 在受控容器环境取证并强化隔离。 |
| 注入防御 | 外部内容已标注，但工具输出未全面检测 | 将工具输出纳入检测与红队。 |
| 检索 | 轻量规则与关键词为主 | 以真实长任务数据评估 AST/语义检索。 |
| 多 Agent | 已限制角色与文件作用域 | 补齐冲突合并和工作区全生命周期审计。 |
| 评测 | 工程治理和单题 runner 已验证 | 预算允许时完成多任务、重复的外部对照。 |

## 改造记录

- 修复上下文 overflow 未进入真实 Agent 路径、BudgetHistory 只写不读等长任务治理缺口。
- 接通安全事件发射，使 SafetyMetrics 不再长期为零。
- 将外部 Harness 改为 JSON v1 协议，并在 Windows 用 Job Object 回收子进程树，规避 `_overlapped` 初始化失败。
- 将 CLI 渲染从主逻辑中拆出，并补充实时进度、运行评分和友好错误输出。

## 维护原则

- 新模块先复用 Protocol、EventBus 和既有配置边界；不绕开授权或评测事实链。
- 每个非平凡改动至少留下一个可运行检查，优先修复共享根因而非单路径补丁。
- 真实能力结论以冻结数据与可信 grader 为准，工程回归不替代外部评测。
