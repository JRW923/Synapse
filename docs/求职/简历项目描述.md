# Synapse：面向代码仓库长任务的本地 Code Agent Harness

> 个人项目

## 项目描述

面向代码仓库长链路任务构建本地Code Agent Harness，作为模型与真实开发环境之间的运行时控制层，统一治理上下文、记忆、工具执行和结果验证，解决多轮执行中的信息膨胀、状态丢失、越界操作及结果不可验证问题。

## 核心职责与贡献

1. 设计可扩展Agent Harness运行时：为解耦模型、规划器与工具，以Protocol、IoC容器与EventBus划分组件边界，统一治理Agent、Session与事件生命周期；接入3家Provider、4类Planner、2种MCP传输，新增Provider约40行、主循环零改动

2. 完善长任务上下文治理机制：为避免历史消息和无关文件挤占预算、仓库内容重复读取，采用Git-aware检索、AST符号提取、相关性排序、四区预算与摘要式compaction；预算按任务类型套模板、依引用率自适应浮动，检索故障最多阻塞10s

3. 构建分层记忆与任务恢复体系：为解决跨轮事实丢失与中断重跑，状态拆为Session、Project、User、Semantic四层，规则随仓库、偏好跨项目复用，写入原子替换；会话跨进程/resume续接并补齐中断调用配对，Git快照回滚零接触用户工作区

4. 强化长任务执行韧性：为防死循环与故障误判，采用打转检测、LLM调用错误四分类、token硬预算与逐工具超时；同文件3次反复修改即回滚快照，累计2次终止任务，网关5xx归为基础设施失败不污染模型统计，180次评测尝试无一被渠道故障误判

5. 建立工具调用安全与执行治理机制：因静态Tool声明无法识别参数副作用，采用action-time鉴权，按工作区、shlex命令链、重定向与SSRF判险；覆盖5级风险决策、14类危险命令、12类敏感路径，决策留签名审计，高风险先拦截或确认

6. 搭建冻结数据与外部grader评测链：因模型自报成功不可信，以gold patch入库验证、completion gate、隔离workspace与不可变登记判分；SWE-bench冻结20题子集三档模型×3评测，success@3为40%-55%、误报率58%-77%，阅卷零故障

## 使用边界

已完成冻结 20 题子集（gold-verified 入库）上三档模型 × 3 次重复的正式 run，但样本量（n=20）与第三方网关口径不支持模型或 Harness 能力排名：各模型 CI 重叠大，数字用于证明"评测链路与治理机制可产出可信结果"，不表述为官方榜单成绩。运行时架构（Protocol + IoC + EventBus、3 Provider / 4 Planner / 2 MCP 传输、零主循环扩展）见[扩展指南](../开发/扩展指南.md)与 `examples/extensions/`，在"一分钟讲解"中口头展开。
