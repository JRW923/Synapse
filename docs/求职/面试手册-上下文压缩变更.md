## 1.2 关键常量：历史压缩（替换）

| 域 | 常量 |
| --- | --- |
| 历史压缩 L1 | 12 万字符软上限；保住最近 6 条工具消息，以及最近读过的 `read`/`grep`/`glob` 结果；只压超过 200 字的块；默认 `elide`，可改 `llm` 先摘要 |
| 历史压缩 L2 | 超过软限或手动/紧急压缩时，把更早的 user/assistant 收成一条 system 摘要，只留最近 4 轮原文；长摘要分块再合并 |
| 手动入口 | CLI `/compact`，Web「压缩」按钮，整句「压缩一下」等同命令，不发给模型当任务 |
| 紧急路径 | 模型报 context length 时先强制压缩再重试一次；任务 token 到 80% 也会强制压一轮（已花掉的 token 不会退回）；100% 仍停 |
| 轮换提示 | `compact_count >= 3` 时提示开新会话，避免摘要反复失真 |
| 多轮注入 | 每一轮用户消息都会用当次检索结果刷新 system prompt，不再冻在第一轮 |

## 1.3 术语表（增补）

## 三十秒稿（替换「压缩怎么做」）

长任务里上下文一直在涨。检索侧还是四区预算：塞不下的参考文件截断或摘要。对话侧改成三级：L1 自动省略旧工具输出；手动或撞窗口时再做 L2，把更早对话收成一条摘要；压过三次就劝你新开会话。CLI 有 `/compact`，网页有按钮，说「压缩一下」也走同一条路径。

## 两分钟稿（补在原「第三层是压缩」之后）

压缩以前只有循环里偷删旧 tool 结果，文档还写成 auto /compact，其实命令并不存在。现在压缩是共享函数：ReAct 每轮、80% 预算、context_length 400、`/compact`、Web 按钮都调用它。默认 L1 仍是廉价 elide；`history_compaction: llm` 才先摘要。L2 才动 user/assistant。system prompt 每轮按最新检索重写，避免多轮只用第一轮仓库上下文。配置项：`history_soft_chars`、`history_keep_recent_tools`、`history_keep_recent_turns`、`compact_rotate_after`。

## 追问备忘

- **「200k 是窗口吗？」** 不是。那是任务累计 token 停跑预算。对话压缩看的是 12 万字符。模型原生窗口我们按报错识别，不写死。
- **「发压缩两个字会怎样？」** 整句匹配才当命令。夹在任务里的「压缩这个文件」仍是普通任务。
- **「压完历史怎么展示？」** 发给模型的是压缩后的消息；Web/CLI 会出一条压缩结果。没有做双副本存原文，避免两套历史对不齐。
- **「和 Claude Code 差在哪？」** 分级、手动入口、撞墙自救、次数劝退已经对齐产品形态。子代理独立窗口、后台会话轮换还没有。
