# Synapse 面试手册

## 项目速览

Synapse 是面向代码仓库长任务的本地 Code Agent Harness。它的重点不是包装模型 API，而是在模型与开发环境之间建立上下文治理、状态恢复、工具授权和结果验证机制。

## 一分钟讲解

我关注的是代码 Agent 在长任务里“能不能持续、可不可以控制、如何证明做完”这三个问题。系统通过 Protocol、IoC 和 EventBus 分离模型、规划、工具与横切治理；通过分区上下文和四层记忆减少重复探索；通过 action-time 授权、进程树回收和工作区边界限制工具副作用；最后以 completion gate、外部 grader 和可复现报告确认结果。这样扩展 Provider 或 Planner 时不需要改 Agent 主循环，也不会绕开安全和评测边界。

## 简历使用

正式项目描述和核心贡献见[简历项目描述](简历项目描述.md)。后端/基础架构岗位优先强调运行时边界、状态持久化和安全治理；Agent 岗位优先强调上下文、记忆和评测证据链。

## 高频追问

### 为什么需要 action-time 授权？

工具名称无法表达真实参数风险。相同的 shell 工具既可能执行安全的 `pytest`，也可能通过重定向、管道或越界路径造成副作用，因此授权必须在得到完整调用参数后判断。

### 如何证明 Agent 完成任务？

模型状态只是一条诊断信号。功能结论需要在干净 workspace 中提取补丁、执行私有测试或外部 grader，并区分 `verified`、未验证和 grader 错误。

### 上下文和记忆如何配合？

上下文是一次模型调用的预算管理，记忆是跨回合或跨会话的状态管理。检索结果先经过预算分区，超限内容摘要或降级；持久化记忆按生命周期隔离并在恢复时检查工作区漂移。

### 沙箱是否足够安全？

默认实现是进程树治理、超时和授权边界，不是完整文件系统隔离。面对不可信代码或高风险任务，应使用受控容器并把该限制明确写入设计和评测报告。

### 任务跑偏了怎么恢复？

任务起点自动打 git checkpoint：用临时 index 复制后 `add -A` + `write-tree` + `commit-tree`，快照挂在 `refs/synapse/checkpoints/` 下，不触碰用户暂存区和工作区，跨进程可恢复。thrashing 检测（同一文件被改 3 次）首次触发时只回滚该文件并提示模型换思路——整区回滚是用户的决定（`/rewind`），因为恢复动作本身也是副作用。restore 只重置 tracked 文件，untracked 一律保留：无法区分"agent 建的"和"用户的"，宁可保守。

### 命令授权怎么处理 shell 语法？

字符串匹配会被引号欺骗（`echo "a && b"` 里的 `&&` 只是参数文本），也会漏掉命令替换。所以用 `shlex` 带 `punctuation_chars` 做真正的 token 化：引号内的操作符不切段，裸露的 `&&`/`;`/`|` 才切；token 流里出现 `$(`、反引号或子 shell 括号就转入确认；引号不平衡直接拒绝——所有误解析都向严格方向失败。

### 外部网页里的 prompt injection 怎么防？

分层处理：外部内容包 `<external-content>` 标注（annotate, not filter）；工具输出再过 InjectionGuard 扫描经典注入签名，命中就在内容前加警告头；关键的是中和伪造的 `</external-content>` 闭合标签——否则攻击者可以用一个字面量闭合标签提前结束标注区，让后半段被当成可信指令。出站方向有 SSRF 防护：私网/环回/云元数据地址和非 HTTP scheme 拒绝，重定向逐跳重校验。

### 是否有正式 benchmark 成绩？

没有。已完成本地回归、官方 SWE-bench 单题 gold smoke 和真实模型单题链路验证，但未完成多任务、重复的跨 Harness 统计实验。因此不把单题或本地适配层表述为官方榜单成绩。

## 追问准备

- 架构：解释 Protocol + IoC + EventBus 如何隔离扩展点与横切逻辑。
- 安全：解释 action-time 授权、工作区边界、注入标注与进程树回收的职责差异。
- 评测：解释外部 grader、数据冻结、预注册、cluster bootstrap 和失败分类为何缺一不可。
- 取舍：承认默认沙箱、轻量检索和真实模型多任务评测的边界，并给出升级条件。
- 恢复：解释 checkpoint 的临时 index 快照为何不污染用户暂存区，以及 thrashing 只回滚单文件的保守理由。
- 编辑自恢复：edit 工具 whitespace-insensitive fuzzy 兜底 + 错误消息给出候选行号，属于 ACI（工具错误消息质量决定 agent 自恢复能力）设计。
