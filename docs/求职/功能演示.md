# 功能演示（面试项目展示指南）

> 用途：把分散在 CLI / Web 两端的功能串成一条可演示主线，既作为验收清单（每条功能都给「具体任务提示词」让你照着敲），也作为面试时完整展示项目的话术底稿。
>
> 默认演示环境：`pip install -e ".[anthropic,openai,google]"` 装好后，先 `synapse` 跑一遍配置向导（写入 `~/.synapse/models.json`）。下文所有 `synapse ...` 命令均假设已配好默认模型。

---

## 0. 一句话定位 + 演示主线

**一句话**：Synapse 是一个「协议优先」的 AI Agent 框架——把 LLM Provider / Tool / Memory / Planner 抽象成接口，核心跑一个真正的 ReAct Agent Loop，配上下文工程、动作时安全边界、事件驱动可观测性和可复现评测。

**推荐演示主线（按从外到内、由浅入深）**：

```
Web 端发任务 → 看实时工具调用/协作 → 弹窗授权(安全边界)
   → 运行评分卡 + 上下文报告(可观测性)
       → 切到 CLI 复现同一任务 / 用 /rewind 回滚(长任务恢复)
           → synapse eval 跑 benchmark(评测闭环)
```

这条线天然覆盖 README 的 6 个核心特色，面试时每段都能对上一个卖点。

## 1. 前置：安装与配置

```bash
# 一行装齐 Anthropic / OpenAI / Google 三协议 SDK
pip install -e ".[anthropic,openai,google]"

# 首次启动进入配置向导（交互式选供应商 / 填 key / 选默认模型）
synapse
```

配置落盘位置：

- `~/.synapse/models.json`：模型与默认 Provider（首次向导与 `/model add` 都写这里）。
- `synapse.yaml`：项目级配置，命令行 `--config` 或 CWD 向上自动探测；优先级高于全局默认，命令行 `--provider/--model/--mode` 临时覆盖最高。

验证点：启动后输入任意问题能正常回复，说明 Provider / 网络 / key 都通了。

## 2. Web 端功能演示

### 2.0 启动（单进程网页 + 自动连接本机工作区）

```bash
# 在最方便的目录启动，网页直接操作该目录
synapse web --workspace /path/to/demo-repo --port 8000
```

浏览器打开 `http://127.0.0.1:8000`。`synapse web` 是单进程：uvicorn 服务 + 本地 Connector 同进程启动，无需配对码。
（远程部署用 `synapse serve` + 用户本机 `synapse connect`，架构见 2.9。）

---

### 2.1 发送任务 + 实时输出区

界面顶部有输入框，Enter 发送、Shift+Enter 换行。

功能点：

- **模型输出**：流式显示思考与回复（SSE 实时推送）。
- **最近工具**：每次工具调用（读文件 / 写文件 / 执行命令）实时以卡片出现，含参数与结果摘要。
- **协作状态**：切到 `swarm` / `hierarchical` 模式时显示多 Agent 分工与进度。

**具体测试提示词**：

```
把当前目录下 README.md 的第一段改成一句话总结，并运行一下项目里的测试
```

验证现象：发送后输入框下方依次出现「模型输出」「最近工具（写文件 + 执行命令）」区块；任务结束有「状态：成功」汇总行。

---

### 2.2 会话管理（新会话 / 左侧切换 / 删除）

- 顶部「新会话」按钮：清空当前上下文，开一个独立 Session。
- 左侧栏「会话」列表：显示历史会话（前 8 位 ID + 条数 + 相对时间）。点击任意一条 → **切换进该会话并加载其历史消息**（即修复后的 Q1 功能）。
- 每条右侧 `×`：删除该会话。

**具体测试提示词**：

```
先发：「用 Python 写一个计算斐波那契的函数」
点「新会话」后再发：「用 Python 写一个快速排序」
点左侧第一条会话 → 应切回斐波那契会话且历史还在
```

验证现象：切换不丢当前会话；左侧列表与 `/sessions` 接口一致。

---

### 2.3 停止任务

运行中顶部「发送」变为「停止」（调用 `POST /run/stop`，经 Connector 命令通道取消当前 job）。

**具体测试提示词**：

```
写一个脚本，循环打印 1 到 1000000，每打印一个 sleep 0.01 秒
```

验证现象：任务进行中点「停止」→ 立即结束，页面提示「已停止任务」；服务端返回 `cancelled: true`。

---

### 2.4 确认授权（动作时安全边界）

需要写文件 / 执行命令等「重要操作」时弹出确认框，三个按钮：

- **拒绝**：本次工具调用不执行。
- **允许一次**：仅本次放行。
- **总是允许此类**：按操作签名记忆（`shell:<首 token>` / `<工具>:<父目录>` 粒度），之后同类不再询问。

设置面板「确认模式」：

- `ask`（默认）：每个重要操作弹窗询问。
- `auto`：全部放行，不再逐个点击。

**具体测试提示词**：

```
在当前目录创建一个新文件 hello.txt，内容为 "hi"
```

验证现象：弹出确认框显示工具名 / 风险等级 / 参数摘要；点「总是允许此类」后，再发一个「写文件」任务不再弹窗。切到 `auto` 模式后任何写操作都不弹窗。

> 设计注：该记忆复用 CLI 的 `ActionAuthorizer.remember_approval`，与命令行「总是允许」签名粒度完全一致，进程级生效（Web 重启后清空，符合 CLI 同进程行为）。

---

### 2.5 上下文报告（Context Engineering 可观测）

会话结束后，对话流尾部有「▸ 上下文报告（点击展开）」。展开后是热力图表格：**Zone / Source / Pri / Tokens / Used / Cited / Rate**。

**何时才有内容**：只有一次运行真正引用了上下文块（检索到的文件、记忆、历史等）才非空；纯闲聊的会话展开显示「运行后才有数据」。

**具体测试提示词**：

```
读一下本项目 src/ 下所有 .py 文件，总结模块职责
```

验证现象：展开上下文报告，能看到被检索文件对应的 zone（如 `retrieval` / `session` / `project`），以及 usage/cited/citation_rate 数值。

---

### 2.6 运行评分卡（四维度 run_score）

任务结束自动插入「运行评分」卡片：**安全 / 过程 / 质量 / 效率** 四维度，并附 `process_hint` 过程提示（与 CLI `/score` 同源，共用 EventBus 事件）。

**具体测试提示词**：

```
重构 src/ 里最复杂的那个模块，并补单元测试
```

验证现象：卡片出现四维度指标；若过程有 thrashing 或低效循环，`process_hint` 给出改进提示。

---

### 2.7 待办列表 / 状态栏 / 会话列表

- **待办**（左侧）：任务中 Agent 生成的 TODO 清单，带 `pending / in_progress / completed` 状态标记，随 `/todos` 接口实时刷新。
- **状态栏**（左侧）：版本 / 模型 / 模式 / 工具数 / 工作区 / Token 预算进度条。
- **会话列表**（左侧）：见 2.2。

**具体测试提示词**：

```
给本项目列一个发布前检查清单，并逐项核对
```

验证现象：左侧「待办」随执行逐项勾选；状态栏 Token 进度条随消耗上涨。

---

### 2.8 设置面板

点「设置」展开：

- **模型配置**：免密钥免费模型（free）或自定义 Provider/Model/Key（custom）；`/model add` 的网页版。
- **确认模式**：`ask` / `auto`（见 2.4）。
- **本会话规划模式**：`react` / `plan_execute` / `hierarchical` / `swarm`，仅对当前会话生效，不写回配置文件。

**具体测试提示词**：

```
切到 plan_execute 模式后：「先给出重构方案，等我确认再动手」
```

验证现象：同一会话后续任务按 plan_execute 先出方案。

---

### 2.9 连接本机工作区（远程架构）

远程服务器只跑 `synapse serve`（网页 + Connector 中继，**不配模型**），用户本机跑：

```bash
# 本机：把指定目录作为受控工作区连到远程网页
synapse connect --server https://agent.example.com --workspace /path/to/local-repo
# 首次绑定加 --pair，按网页提示输入配对码
```

网页点「连接本机」生成配对码，本机 `synapse connect --pair` 输入即绑定。架构要点：网页（uvicorn 线程）与本地 Connector（主线程事件循环）**只通过 HTTP + 命令队列通信**，任务在本机工作区执行，模型密钥不上传服务器。

## 3. CLI 端功能演示（全量）

### 3.1 交互式 REPL + 斜杠命令

直接 `synapse` 进入 REPL。支持的斜杠命令（面试时挑常用的演示即可）：

| 命令 | 作用 | 演示提示词 / 操作 |
| --- | --- | --- |
| `/help` | 帮助 | 直接敲 |
| `/model` | 显示/切换模型 | `/model 2` 切到第 2 个已配置模型 |
| `/model add` | 添加模型配置 | 进入向导，填供应商 / key / 模型 |
| `/provider` | 显示/切换供应商 | `/provider openai` |
| `/reset` `/clear` | 清空当前会话 | 敲完上下文归零 |
| `/memory` | 上下文占用 / 引用率 | 跑完检索任务后看 citation 行 |
| `/session` | 当前会话 id / 落盘路径 | 敲完显示 `~/.synapse/sessions/<id>.json` |
| `/sessions` | 列出历史会话 | 显示最近 10 个 |
| `/resume` | 恢复会话 | `/resume` 恢复最近一个；`/resume <id>` 指定 |
| `/context-report` | 上下文引用热力图 | 跑完检索任务后看 zone 表（同网页 2.5） |
| `/score` | 四维度运行评分 + 过程提示 | 任务后敲（同网页 2.6） |
| `/todos` | 当前 TODO 清单 | 任务中敲看进度 |
| `/checkpoint` | 手动打 Git checkpoint | `/checkpoint before-refactor` |
| `/rewind` | 回滚工作区到 checkpoint | `/rewind 1` 回滚到最新快照 |
| `/exit` `/quit` | 退出 | — |

**长任务恢复演示（对应 README 卖点 2）**：

```
# 先制造一次可回滚的改动
/resume 进入会话后发：「重构 auth 模块」
# 跑偏了就 /rewind 1 把工作区文件回滚到任务前状态，提示换思路
```

> 机制：任务起点自动打 Git checkpoint（临时 index 快照，不碰用户暂存区/工作区）；thrashing 首次触发自动回滚并提示换思路。

### 3.2 `synapse run` —— 一次性任务

```bash
# 基础
synapse run "修复 src/parser.py 的边界条件，并运行相关测试"

# 指定供应商/模型/规划模式
synapse run --provider openai --model gpt-4o "重构认证模块并补充测试"
synapse run --mode plan_execute "重构认证模块"

# 启用外部工具（HTTP / DB / Browser，默认关闭）
synapse run --enable-external-tools "抓取 https://example.com 并总结"

# 接入 MCP 服务器（stdio 命令或 streamable-HTTP URL）
synapse run --mcp-server "fs:npx -y @modelcontextprotocol/server-filesystem ." "列出当前目录大文件"
synapse run --mcp-server "api:https://mcp.example.com/mcp" "调用远程工具"

# 非交互全自动批准（等价于 Web 的 auto 模式）
synapse run --yes "批量重命名 *.txt 为 *.md"

# 恢复会话继续
synapse run --resume "把上次的方案落地成代码"
```

**验证点**：`--yes` 下写/执行类操作不再询问直接执行；`--resume` 把新任务追加到旧历史。

### 3.7 `synapse eval` —— 可复现评测闭环

```bash
# 内置单题 fixture，只验证 Agent→workspace→grader→report 链路
synapse eval process_quality

# 真实修改 + pytest grader
synapse eval repo_pytest --max-tasks 5 --report eval-results/repo.json

# 离线 terminal fixture
synapse eval terminal_smoke

# Terminal-Bench 风格本地数据集（需 --dataset）
synapse eval terminal_bench --dataset tasks.jsonl

# 重复 N 次，输出 Pass@k 与 95% CI
synapse eval repo_pytest --repeat 3 --report eval-results/repo.json

# 可信评测数据才允许在宿主机执行 grader
synapse eval terminal_bench --dataset tasks.jsonl --trusted-host-execution
```

benchmark 类型：`process_quality` / `repo_pytest` / `swebench` / `terminal_smoke` / `terminal_bench`。报告输出 JSON + 双语 HTML Dashboard + CSV（`synapse eval.visualize <json>` 生成可视化）。

### 3.8 `synapse experiment` —— A/B 实验

```bash
synapse experiment \
  --name "memory-ablation" \
  --config-a '{"provider":"anthropic"}' \
  --config-b '{"provider":"anthropic","runtime":{"eval_ablation":{"memory":true}}}' \
  --task "实现一个 LRU 缓存" \
  --report eval-results/exp.json
```

同轮 A/B 随机交错，支持多指标独立方向、配对 bootstrap CI、随机化检验；按任务独立 workspace 配对。

## 5. 面试串联话术（把演示讲成项目）

每段演示 → 对应架构卖点 + 高频追问应对：

- **Web 实时工具调用 / 协作状态** → 「协议优先 Harness + 真正的 Agent Loop（不是单轮函数调用）」。追问「为什么不直接用 LangChain？」答：Planner 是接口，ReAct/Plan-Execute/Hierarchical/Swarm 共享，换策略不改业务代码。
- **确认弹窗 + 总是允许此类** → 「Action-time 安全边界：每次工具调用按风险/路径/命令链重新授权，命令链用 shlex 解析（`$()`/反引号触发确认），签名粒度复用 CLI 的 `ActionAuthorizer`」。追问「Web 和 CLI 安全一致吗？」答：同一套授权器，记忆签名粒度完全一致。
- **上下文报告 / 运行评分卡** → 「事件驱动可观测性：Token/工具/授权/Agent 事件统一进 EventBus，run_score 四维共用同一事件源」。追问「怎么防 prompt injection？」答：外部内容带 trust annotation，web/db/browser 输出过 InjectionGuard 扫描。
- **`/rewind` / checkpoint** → 「长任务跑偏有恢复路径：Git checkpoint + thrashing 自动回滚」。
- **`synapse eval` / `experiment`** → 「可复现评测闭环：Pass@k + 95% CI + 按 repository cluster 重采样，JSON 为事实来源」。追问「benchmark 成绩代表模型能力吗？」答：明确区分 fixture 验证链路与官方 benchmark 成绩，不夸大。
- **`synapse web` vs `serve`+`connect`** → 「本地单进程 vs 远程中继：Connector 与服务器只走 HTTP + 命令队列，模型密钥留在用户本机」。

> 一句话收尾：「Synapse 的价值是把 Agent 的工程复杂度收敛到一组可替换的协议接口上——安全、可观测、可评测，且 Web/CLI 两端行为一致。」
